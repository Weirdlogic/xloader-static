#Delivery — how does a .bat-named PE execute? (unresolved)

What is known. MalwareBazaar records delivery_method: email_attachment (reporter-declared), no email or archive (intelligence.mail: null), and every sandbox ran the bare executable (ANY.RUN stored it as exe). The same lure theme appears in two sibling builds on 2026-10-12, both hitting the same community pixel-loader rules as this sample:

Across 2,073 PE submissions for Formbook, AgentTesla, Remcos, Snake and VIPKeylogger (2025-07 → 2026-10), 39 carry a .bat name, 25 .com, 9 .scr, 5 .pif; threatcat_ch usually submits .exe (151) and only occasionally .bat (10). The .bat naming is therefore not a single reporter's convention.

Why it matters. Explorer double-click (ShellExecute) chooses the handler by extension, so a .bat goes to cmd.exe as a script and a PE would not run. CreateProcess inspects the file content (MZ) instead, so a .bat-named PE started by a script, an archive tool or another launcher that calls CreateProcess directly would execute. A .com-named PE (the sibling's name) does execute on double-click.

Status. The delivery container is not public, so the execution path is not established. Candidate explanations: the attachment was an archive or disk image whose member had another name; a separate script launched it via CreateProcess; or the .bat name was introduced by gateway/extraction tooling. Planned test: in an isolated Windows VM, rename a benign PE to .bat and record what Explorer, Outlook attachment preview and common archive tools (7-Zip, WinRAR, Windows built-in ZIP) do with it — no malware required.

Payload cipher (PnK3ZS2bNP). With K = Encoding.<?>.GetBytes(key) and n = data length, for j = 0 … n: i = j mod n, P[i] = ((P[i] ^ K[j mod |K|]) − P[(i+1) mod n] + 256) mod 256; then the last byte is dropped. Because each step only mixes c[i], c[i+1] and one key byte, K[i mod |K|] = c[i] ^ ((p[i] + c[i+1]) mod 256). Using the standard DOS stub as known plaintext gave a keystream with period 7 → key hSLKhTt (single-byte encoding). #How the dispatcher selects a handler

  • entry keeps all state in one stack block. The dispatcher FUN_004010a0 finds it by scanning the stack for the marker 0x109ddd80 (planted at 0x40276e, mov [ebp-0x182],0x109ddd80) and sets ctx = marker − 0x346. Hence ctx[off] is entry's local_(0x4cc−off) in Ghidra naming; verified on five fields (command ctx[0x185] = local_347, seed ctx[0x362] = local_16a, selector pointer ctx[0x155] = local_377 = &local_176, selector ctx[0x356], marker ctx[0x346] = local_186).

#5.2 Cipher (FUN_00004440 and helpers) — tools/fb_cipher.py

All stage-5 layers use one routine, driven by a state block whose sizes are hidden as split constants (0x78 + 0x88 = 256, 0x0e + 6 = 20 key bytes, 0xdb − 0xda = 1, sentinel 0x9f015014). Order:

  1. pass A — backwards difference: d[n−1−i] −= d[n−i] for i = 1…n−1
  2. pass B — forwards difference: d[i−1] −= d[i]
  3. RC4 with a 20-byte key
  4. pass A, 5. pass B

Mode byte 0x8d = subtract (decrypt); 0x80 = add. The port was validated on every layer below.

#Open questions

  1. Real-C2 confirmation. www[.]minha[.]cc is the separately encrypted entry the code substitutes into slot 11; whether it is live, and whether other builds of the same campaign share it, needs passive DNS / threat-intel lookups (not done here). Entry 21 (20-byte value) is not yet explained.
  2. Stage 5 version. Match the build against Zscaler's published v8.x hashes/markers to pin the version.
  3. CAPE behaviours not yet located statically: FIPS policy query, AMSI provider enumeration, vectored exception handler, timestomp to 2082.
  4. Host process for hollowing. Decrypt stage 3's strings (F6cLl9xwKFMQVo1L8x6) to name the .NET Framework binary chosen by PvR3IDLAdk, the HKLM registry value, and the config fields; or read them from the Triage/CAPE process trees.
  5. Detection validation — partly done (see Detections); still required:
    • goodware: run the YARA rules over a large set of benign .NET WinForms binaries (especially image-heavy apps and legitimate Assembly.Load users);
    • cross-sample: test the generic rule on independently collected samples with different names/resources;
    • telemetry: confirm which events the KQL/EQL hunts actually see, from an isolated detonation or a benign harness that reproduces CallByName(AppDomain, "Load") with a bitmap-carried assembly.
